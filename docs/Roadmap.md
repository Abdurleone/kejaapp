# Roadmap

The canonical, detailed history is [CHANGELOG.md](https://github.com/Abdurleone/kejaapp/blob/main/CHANGELOG.md) in the repo — this page is a summarized Completed/Next view for wiki readers.

## Completed

- Backend proof-of-concept; auth, account management, property listings, property image management, saved properties, pricing, property inquiries, viewing requests, reviews, notifications, agency verification, admin moderation, movers, static web frontend, tests, seeding, and an Insomnia collection.
- React Native (Expo) mobile app MVP for iOS/Android — auth, discover/search, property detail, saved favorites, inquiries, viewing requests. Verified end-to-end on a real Android emulator, not just the Expo web preview.
- CI (GitHub Actions), Docker images for backend/frontend, docker-compose for local/staging, and health check endpoints.
- ESLint across all three packages wired into CI, Dependabot for weekly dependency updates, a Jest + React Native Testing Library setup for mobile.
- Seeded demo data expanded to 9 counties (11 available properties) with matching mover coverage; a property detail page + inquiry/viewing-request forms added to the web frontend.
- Fixed hidden star-rating summaries on Discover/Saved cards; seeded real review data; fixed a seeder bug that silently zeroed every property's rating on each reseed (a stringified ID passed into a raw Mongoose aggregation `$match`).
- Web owner workspace switched from hardcoded placeholder numbers to real, server-scoped data (`GET /api/inquiries/received` + `GET /api/properties/mine`).
- Skeleton loading UI (pulse animation) on all card/list-shaped loading states, web and mobile.
- Backend/HTTP log timestamps switched to Nairobi time (`Africa/Nairobi`, UTC+3) instead of UTC.
- Dependency upgrades via Dependabot: frontend to React 19 + Vite 8, mobile to Expo 57/React Native 0.86 (with `eslint`/`jest` deliberately held back pending `eslint-config-expo`/`jest-expo` compatibility).
- Fixed the landing page's "Sign in" button never rendering (the auth modal was nested inside the wrong branch of a ternary).
- Automated API testing: migrated to [supertest](https://github.com/ladjs/supertest), added a real-database end-to-end API flow test. Surfaced and fixed three real bugs along the way (a test-helper ordering bug, a rating-recompute cast bug, and a stale-cache-after-review bug).
- Built a role-aware Dashboard on both web and mobile, consuming the previously-unused `GET /api/dashboard/summary` endpoint — the first landlord/agency/admin-facing screen on mobile.
- Added Edit/Create listing flows for landlords/agencies on both web and mobile (previously only reachable via seeding/direct API calls).
- Consolidated the theme to a single dark-green, Kenya-flag-only palette with an explicit Light/Dark radio toggle.
- Corrected the admin role to match its user story: removed admin from every listing-management role check on the backend and frontend/mobile, replacing the web `AdminPage` placeholder with a real user-management console.

- **Username login**: registration assigns (later: lets users choose) a username as an alternate login identifier. See [Authentication](Authentication) for the current behavior.
- Small alignment fixes on the Discover radius/location filters (web `.header-actions` vertical alignment, mobile "Near me" button touch-target height).
- **Follow-up to username login**: users now choose their own username at registration (free text) instead of receiving an auto-generated one, with up to 3 available suggestions shown on conflict. Generalized the backend's `ApiError`/error handler to carry structured extra data through to error responses.

Found and removed a fully dead predecessor in the process: a `fcmTokens` array on the `User` model and a `POST /api/auth/fcm-token` endpoint that only ever wrote to it, with no Firebase/sending code behind it at all.

- **Role-scoped property access, mover pickup distance, and a notification bell**: landlords/agencies can no longer view other owners' full property details (previously only blocked from browsing the Discover list, not a direct link) — scoped to their own listings everywhere now. Mover requests now capture the tenant's device location at request time and return a computed pickup-to-dropoff distance (haversine, against the destination property's coordinates, never stored so it can't go stale). Added a bell badge (web nav, mobile bottom tab) showing the unread notification count, polled every 30 seconds and cleared immediately on opening Notifications via a new bulk `PUT /api/notifications/read-all` endpoint.

Also closed a real account-deletion gap found while writing the Data Protection Policy: `DELETE /api/auth/me` previously skipped mover profiles/verifications/requests, feedback, saved searches, and device tokens — it now cascades through all of them.
